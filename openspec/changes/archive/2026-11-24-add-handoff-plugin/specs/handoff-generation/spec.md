## ADDED Requirements

### Requirement: In cold mode, /handoff never reaches the main model
When the mode is cold (see `handoff-mode`), the hook SHALL answer `decision: "block"` in every
case: success, pipeline error, Haiku timeout or unreadable transcript.

#### Scenario: Success
- **WHEN** the pipeline produces the handoff
- **THEN** the hook blocks with the delivery message defined in `handoff-delivery`

#### Scenario: Pipeline failure
- **WHEN** an exception is raised or the Haiku call times out
- **THEN** the hook still blocks, with the error in `reason`, and writes no handoff file

#### Scenario: Any other prompt
- **WHEN** the user types a prompt that does not start with `/handoff` or
  `/session-handoff:handoff`
- **THEN** the hook exits with no output and the prompt goes through unchanged

### Requirement: User focus
The text after `/handoff`, without flags, SHALL be included in the handoff instructions as the
user's priority, in both modes: the Haiku prompt and the `<session-handoff>` block.

#### Scenario: With focus
- **WHEN** the user types `/handoff continue with the parser bug`
- **THEN** the instructions contain `User priority: continue with the parser bug`

#### Scenario: Without focus
- **WHEN** the user types only `/handoff`
- **THEN** the instructions contain no priority line

### Requirement: Haiku sees the repository state and the recency rule
The input of the Haiku call SHALL start with a `## Repository state (authoritative, generated by
code)` section holding the same git text as `Branch / commits`, redacted and with mentions
neutralized, followed by the digest. The saved digest file SHALL NOT include that section. The
Haiku system prompt SHALL state that the end of the conversation is the current state (later turns
override earlier ones) and that the Repository state section is authoritative for branches,
commits and uncommitted changes and must never be contradicted.

#### Scenario: Git state reaches Haiku
- **WHEN** the mode is cold and `cwd` has a feature branch with a recent commit
- **THEN** the input sent to Haiku starts with the Repository state heading followed by the
  branch and commits text, then the digest

#### Scenario: Secrets and mentions in the git text
- **WHEN** the git text holds `TOKEN=abc` or an `@/path` mention
- **THEN** the Repository state section sent to Haiku has the value redacted and the mention
  neutralized

#### Scenario: The rules are in the system prompt
- **WHEN** the system prompt for Haiku is built
- **THEN** it contains the recency rule and the authoritative-repository-state rule

### Requirement: Haiku on the subscription
Cold generation SHALL run `claude -p --model haiku` with an environment that has no
`ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`, `CLAUDE_CODE_USE_BEDROCK` or
`CLAUDE_CODE_USE_VERTEX` (`CLAUDE_CODE_OAUTH_TOKEN` is the subscription and stays), outside the
project's `cwd`.

#### Scenario: API key in the environment
- **WHEN** the hook environment has `ANTHROPIC_API_KEY`
- **THEN** the `claude` subprocess does not receive it

#### Scenario: Other provider routing in the environment
- **WHEN** the hook environment selects Bedrock or Vertex or sets `ANTHROPIC_BASE_URL`
- **THEN** the `claude` subprocess does not receive those variables

### Requirement: Failures outside the pipeline still block
`hooks/run.py` SHALL exit with code 2 and a one-line reason on stderr when the prompt is
`/handoff` and the hook cannot run at all (Python older than 3.11, the package failing to import,
or any exception escaping the pipeline or its logging setup). Any other prompt SHALL exit 0
silently.

#### Scenario: Broken install
- **WHEN** the package raises on import and the prompt is `/handoff`
- **THEN** the hook exits 2 with the reason on stderr and the prompt does not reach the model

### Requirement: Fixed format and size limit
The handoff SHALL have the sections `Goal`, `Current state`, `Decisions and why`,
`Ruled out and why`, `Next steps`, `How to verify`, `Key files` and `Branch / commits`. The last
two SHALL be generated by code. The handoff SHALL end with the digest path, and its total length
SHALL be at most 32,000 characters.

#### Scenario: Haiku answer too long
- **WHEN** the model answer plus the deterministic sections exceed 32,000 characters
- **THEN** `Key files` is trimmed first until it fits and, if that is not enough, the end of the
  model text; the digest path line is always kept

#### Scenario: Invalid Haiku answer
- **WHEN** the answer is empty or lacks `# Handoff`, `Goal`, `Current state` or `Next steps`
- **THEN** the hook blocks with an error and saves no handoff, but it does save the digest

#### Scenario: Answer wrapped in a code fence
- **WHEN** the answer is the whole document inside one outer markdown fence
- **THEN** the fence is removed and the document is validated and saved without it

#### Scenario: Git command fails
- **WHEN** a git command fails or times out
- **THEN** its part of `Branch / commits` reads `(unavailable)`, never `(clean)` or `(none)`

#### Scenario: Project without git
- **WHEN** `cwd` is not a git repository
- **THEN** `Branch / commits` reads "no git repository"

### Requirement: Storage and retention
On each success, the system SHALL save the handoff and the digest under
`~/.claude/handoffs/<cwd-slug>/`, named `<timestamp>-<session8>`, and SHALL keep only the last 10
pairs per project.

#### Scenario: Eleventh handoff of a project
- **WHEN** 10 pairs are already saved and another one is generated
- **THEN** the oldest pair is deleted and 10 remain
